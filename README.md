# Restaurant Guests Forecasting

Прогнозирование количества гостей ресторана на следующие дни
на основе исторических данных посещаемости, календарных признаков и информации
о ресторанах.

## Задача

Целевая переменная — `guests`: количество посетителей ресторана в конкретный день.

## Что сделано

- проведён EDA исходного датасета;
- восстановлен дневной календарь для ресторанов;
- добавлены временные, календарные, лаговые и rolling-признаки;
- проверены признаки на data leakage;
- выполнен временной train/validation split;
- построен baseline `lag-7`;
- обучены и сравнены LR, CatBoost, Random Forest и Prophet;
- качество моделей оценено на одном validation-периоде по MAE и RMSE;
- основная логика вынесена в переиспользуемые модули `src/`;
- подготовлен CLI для получения прогноза сохранённой моделью.
  
## Данные

Для задачи выбран датасет Kaggle **Recruit Restaurant Visitor Forecasting**.

Он подходит для задачи прогнозирования посещаемости, поскольку содержит
дневную историю посещений нескольких сотен ресторанов и охватывает период
более 12 месяцев: с 2016-01-01 по 2017-04-22. Всего в датасете около
829 ресторанов.

Исходный датасет состоит из трёх основных таблиц:

- `air_visit_data.csv` — фактическое количество гостей (`visitors`) для
  ресторана (`air_store_id`) по датам;
- `air_store_info.csv` — характеристики ресторана: жанр и район;
- `date_info.csv` — календарная информация, включая праздничные дни. :contentReference[oaicite:2]{index=2}

Исходная таблица посещаемости содержит только дни, для которых есть запись.
Поэтому на этапе подготовки данных календарь восстанавливается отдельно для
каждого ресторана в пределах его фактического периода наблюдений. Это позволяет
корректно строить временные признаки и не создавать искусственную историю до
открытия ресторана.

В проекте эти данные объединяются в единую таблицу с ключом
restaurant_id + date, где guests является целевой переменной.

Датасет позволяет проверить подходы, специфичные для временных рядов: недельную сезонность, праздничные
эффекты, лаговые признаки и скользящие статистики.

## Модели и валидация

В качестве бейзлайна использован lag-7: прогнозом на день является значение
`guests` для того же дня недели неделю назад. Это простой сезонный ориентир,
с которым сравниваются все модели.

В сравнении использованы три подхода:

- **Ridge** — линейная модель с L2-регуляризацией. Используется как
  интерпретируемый линейный baseline на признаках календаря, лагов и
  скользящих статистик.
- **CatBoost** — бустинг по деревьям, использующий категориальные признаки
  без ручного One-Hot Encoding. Модель позволяет учитывать нелинейные
  зависимости и взаимодействия между признаками.
- **Prophet** — отдельный подход к моделированию временного ряда с трендом
  и сезонностью. Модель обучалась независимо для каждого `restaurant_id`,
  поэтому из-за времени обучения сравнение проведено на 5 ресторанах с
  самой длинной историей, а не на всём датасете.

Random Forest в итоговое сравнение не включён: при One-Hot Encoding
`restaurant_id` обучение на полном датасете занимало существенно больше
времени относительно получаемой от модели ценности.

## Метрики

Основная метрика — **MAE**: она показывает среднюю абсолютную ошибку
прогноза в количестве гостей и поэтому непосредственно интерпретируется в
терминах задачи.

Дополнительно рассчитаны **RMSE**, чувствительная к большим ошибкам, и
**MAPE**, позволяющая сопоставлять ошибку между ресторанами с разным
объёмом посещаемости.

## Результаты

Prophet и модели с признаками оцениваются на разных выборках, поэтому
результаты приведены отдельно.

### Полный датасет — 829 ресторанов

| Модель      |  MAE |  RMSE |   MAPE |
|-------------|-----:|------:|-------:|
| CatBoost    | 6.89 | 11.55 | 60.97% |
| Ridge       | 7.49 | 11.94 | 66.93% |
| Naive lag-7 | 8.90 | 15.19 | 74.43% |

### 5 ресторанов — сравнение с Prophet

| Модель       |      MAE |      RMSE |       MAPE |
| ------------ | -------: | --------: | ---------: |
| **CatBoost** | **8.21** | **11.30** | **49.82%** |
| Ridge        |     8.93 |     12.02 |     55.57% |
| Prophet      |     9.03 |     11.99 |     56.88% |
| Naive lag-7  |    10.74 |     14.83 |     61.30% |


## Что это значит для бизнеса

CatBoost ошибается в среднем на 6,89 гостя в день против 8,90 у наивного
прогноза «как неделю назад» — точность выросла на 23%. Для ресторана с
типичным потоком около 15-20 гостей в день такая ошибка заметна, но
приемлема для планирования смен с запасом в 1-2 человека. MAPE (61%)
высокий из-за ресторанов с малым потоком, где даже пара гостей — большая
доля от общего числа, MAE показательнее.

Для закупок продуктов точности пока недостаточно без дополнительного
запаса. Прогноз стоит использовать как ориентир для планирования смен,
а не как точное число для закупок без страхового запаса.


## Что бы улучшила, если бы было больше времени

- Сравнить Prophet на большем количестве ресторанов. Текущая оценка
  использует только 5 ресторанов и не позволяет делать вывод о качестве
  метода на всём датасете.
- Проверить итоговый `forecast()` в режиме полного walk-forward для
  7-дневного рекурсивного прогноза. Сейчас валидация оценивает one-step-ahead
  прогноз.
- Заменить один holdout на несколько временных разбиений с расширяющимся
  train-окном и `gap`.
- Добавить интервалы неопределённости к точечному прогнозу, например через
  квантильный CatBoost или Monte Carlo.
- Проверить влияние длинных пропусков в истории. Сейчас такие периоды
  исключаются из target, но отдельно не оценивается их влияние на лаги и
  rolling-признаки.
- Добавить Docker для воспроизводимого запуска проекта.
